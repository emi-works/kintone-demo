# 見積→請求 連動アプリ（kintone × JavaScript × REST API）

## 困りごと

**「見積書から請求書を作るとき、同じ内容を何度も手入力している」**

kintone で見積を管理していても、請求書は Excel や別システムで作り直している会社は少なくありません。同じ顧客名・件名・明細を何度も打ち直すので、時間がかかるうえに、金額の打ち間違いや転記漏れも起きます。

さらに 2023年からのインボイス制度で、請求書には「税率ごとの合計と消費税額」「登録番号」の記載が必要になりました。kintone 標準の計算フィールドでは、明細を税率ごとに分けて集計するのが難しく、「インボイスに対応した請求書を kintone から出せない」という声もよく聞きます。

帳票の出力も、通常は月額制の有料プラグインに頼ることになります。

## 解決

見積管理・請求管理の2つのアプリを作り、JavaScript カスタマイズと REST API で次のことを実現しました。

1. **インボイス制度に対応した税計算**
   明細ごとに税率（10%／軽減8%）を選ぶだけで、税率ごとの対象額・消費税・合計を自動で計算します。消費税は「税率ごとの合計 × 税率」を1回だけ計算し、端数は切り捨てます（明細ごとに消費税を計算して足すと、制度のルールとずれるため）。

2. **ボタン1つで見積 → 請求に転記**
   「受注」になった見積の画面に「請求書を作成」ボタンが出ます。押すと、請求番号の採番から、明細を含めた請求書の登録、見積側の「請求済み」への切り替えまでを一度に行います。手入力はゼロです。

3. **有料プラグインなしで帳票を出力**
   「印刷」ボタンで A4 の見積書・請求書を表示し、そのまま印刷や PDF 保存ができます。登録番号、税率ごとの消費税、軽減税率品目の ※ 印など、適格請求書に必要な項目をそろえています。

4. **細かな手間もなくす**
   見積番号・請求番号を年ごとに自動採番（`Q-2026-0001` など）し、有効期限（見積日＋30日）と支払期限（請求日の翌月末）も自動で入ります。請求一覧では、支払期限を過ぎた未入金を赤く表示します。

## 工夫した点

- **二重作成を防ぐ**
  ボタンを押した瞬間に見積を読み直し、すでに請求書があれば作成しません。ボタンは処理中に押せなくし、見積の更新時には「読み直した後に誰かが更新していないか」も確認しています。万一、請求書の作成後に見積の更新だけ失敗した場合も、作成済みの請求番号を伝えて、状況が分かるようにしています。

- **業務の流れに沿った制御**
  請求書を作れるのは「受注」の見積だけです。「請求済み」は手で選べないようにし（一覧画面での直接編集も対象）、ステータスと実際の請求書が食い違わないようにしています。

- **計算の正確さ**
  0.1 × 3 のような小数の計算で 1 円ずれることがないよう、消費税は整数で計算しています。数量 2.5 人日のような小数の明細にも対応しています。

- **有料プラグインに頼らない帳票**
  ブラウザの印刷機能と印刷用の CSS だけで A4 帳票を作りました。プラグインの月額費用がかからず、レイアウトも自由に変えられます。

- **2つのアプリで共通のコード**
  税計算・採番・帳票は共通ファイル（common.js）にまとめ、両アプリで同じものを使っています。片方だけ直し忘れることがなく、保守しやすい構成です。

- **アプリの構成もコードで管理**
  フィールド・フォームの配置・一覧を定義ファイルにまとめ、REST API で組み立てるスクリプトを用意しました。別の環境にも同じアプリを数秒で再現できます。

## 使用技術

- kintone（2アプリの設計・連携）
- kintone JavaScript API（イベント処理、サブテーブルの計算、保存時チェック）
- kintone REST API（アプリ間のレコード登録・更新、採番、アプリ構築の自動化）
- CSS（印刷用レイアウト）
- Node.js（アプリ構築・デモデータ登録のスクリプト）
