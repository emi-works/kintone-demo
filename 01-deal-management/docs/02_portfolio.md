# 案件・顧客管理アプリ（kintone × JavaScript）

## 困りごと

**「Excelの案件管理表をkintoneに移したら、入力漏れと期限切れが増えた」**

Excelのころは、担当者が表を上から眺めて「この案件、金額が空いているな」「この期限、もう過ぎているな」と気づけていました。
ところがkintoneに移すと、案件は1件ずつ別の画面になり、表を一目で見渡すことがなくなります。その結果、

- 受注にしたのに受注金額が入っていない、失注にしたのに理由が書かれていない
- 次回アクションの期限が過ぎていても誰も気づかない

といった問題が起きやすくなります。
kintone標準の「必須項目」設定はいつでも同じ項目を必須にするため、「受注のときだけ受注金額を必須にしたい」という使い分けができないことも原因です。

## 解決

kintoneのJavaScriptカスタマイズで、次の3つを作りました。

1. **ステータスに応じた入力項目の出し分け**
   ステータス（リード／提案中／見積提出／受注／失注）を選ぶと、その段階で必要な項目だけが表示されます。入力する人が迷わず、画面もすっきりします。

2. **ステータスごとの必須チェック**
   「見積提出なら見積金額と提出日」「受注なら受注日と受注金額」「失注なら失注理由」など、段階ごとに必須項目を切り替えます。未入力のまま保存しようとすると、該当項目に赤字でエラーを出し、保存を止めます。

3. **期限が近い・過ぎた案件の色分け**
   一覧画面で、次回アクション期限を過ぎた案件を赤、3日以内の案件を黄色で表示します。一覧の上部には、アプリ全体の「期限切れ◯件／3日以内に期限◯件」を表示します。

## 工夫した点

- **一覧画面からの「抜け道」もふさいだ**
  kintoneは一覧画面でも直接編集（インライン編集）ができます。入力画面だけをチェックすると、一覧でステータスだけ「受注」に変えて必須項目を飛ばせてしまうため、一覧からの保存にも同じチェックをかけ、「詳細画面から編集してください」と案内しています。

- **入力前に「何が必須か」を見せる**
  保存してからエラーで知らされるのはストレスになるため、入力画面の上部に「ステータス『見積提出』では次の項目が必須です：見積金額、見積提出日」と、ステータスを切り替えるたびに案内を出しています。

- **件数はアプリ全体で数える（REST API）**
  一覧に見えている件数だけを数えると、2ページ目以降に期限切れが隠れていても気づけません。kintone REST APIで「進行中かつ期限切れ」のレコード件数を取得し、絞り込みやページに関係なく正しい件数を表示しています。件数だけが必要なので、取得するデータは最小限にしています。

- **色だけに頼らない表示**
  色の見分けがつきにくい方でも分かるよう、行の左端の線と「3日超過」「あと2日」といった文字のバッジを併用しています。

- **終わった案件は警告しない**
  受注・失注の案件は期限の色分けや期限の必須チェックの対象外にし、本当に対応が必要な案件だけが目立つようにしています。また、一度「失注」にしてから戻した場合は失注理由を自動で空にし、集計のずれを防いでいます。

- **あとから直しやすいコード**
  ステータスごとの「表示する項目」「必須の項目」を1か所の設定（`STATUS_RULES`）にまとめ、フィールドコードも定数にしています。運用が変わって必須項目を増やしたいときも、設定を1行書き換えるだけで対応できます。コードには処理の意図を日本語コメントで残しています。

## 使用技術

- kintone（アプリ設計・一覧設定）
- kintone JavaScript API（イベント処理、フィールドの表示切り替え、保存時チェック）
- kintone REST API（レコード件数の取得）
- CSS
